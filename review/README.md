## 資料夾內容

```
A-資料缺漏與異常/    A1–A7 稽核腳本（run-all.R 一鍵，約 200 秒；A7 單獨跑）
  output/            腳本產出的 csv，帶 BOM，可直接用 Excel 開

  往來信件/          與票證協作平臺的信件與電話紀錄
D-方法與一致性/      複查-*.R 與同名 .log；結論寫在同資料夾的 複查-*.md
  output/            csv
E-交付範圍缺口/      E1 五次以上族群側寫腳本與輸出
```

腳本命名：`<項目編號>-<主題>.R`（A 類）或 `複查-<項目編號><主題>.R`（D 類）。每支腳本開頭註解寫問題、做法、輸出。

## 維護規則

1. **新發現**：寫在項目資料夾裡的 md（腳本旁邊），`問題清單.md` 只加一行連結。
2. **做決定**：先在 `裁示紀錄.md` 加一列，再改程式或文字。
3. **做完事**：把 `待辦.md` 那一行刪掉；落地位置補進裁示紀錄。
4. **收工**：更新 `../README.md` 的「目前狀態」。

不另外記異動紀錄，git log 就是。

## 執行環境

- R 4.5.1，套件 data.table、openxlsx。資料 `../data/` 約 1.3 GB，腳本只讀必要欄位，一般筆電可跑。
- A 類與多數 D 類腳本以自身位置推算 repo 根目錄。少數腳本硬寫 `d:/Github/115_Final-Report`（`複查-花蓮公路TPASS低谷分解.R`、`複查-全部乘客臺東市區-新舊xlsx逐格比對.R`、`複查-整併版vs獨立腳本-臺東市區.R`、`複查-異常值旗標*.R`、`複查-C3異常值*.R`），換機器要改開頭那一行。
- 清理規則與 `實作測試/115期末.Rmd` 一致，稽核對象就是報告實際用的資料。
